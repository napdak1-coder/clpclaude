# 2ST HM TOTAL — 알고리즘에 넣지 않는 실무자 컨텍스트

이 문서는 실무자 분배에서 관찰된 패턴 중 **알고리즘에 절대 룰로 반영하면 안 되는** 것을 보관한다.
사람이 손으로 짤 때만 활용하고, 시스템이 자동 분배할 때는 무시해야 하는 신호.

---

## ❌ 알고리즘 룰로 넣지 말 것

### ① 부킹 번호 chronological 그룹

관찰: 실무자 분배에서 부킹 번호(FISGN260###) 가 같은 시점·근처 번호끼리 묶이는 경향.
- 40FT-1: 후반 부킹 (260338~260391)
- 40FT-2: 중반 부킹 (260276, 260344~260378)
- 20FT-3: 산발 (260332, 260354, 260374, 260386)

**왜 룰로 안 쓰나:**
- 부킹 번호는 발급 시점·시스템 카운터일 뿐 적재 우선순위가 아님.
- 같은 시점 작성된 부킹이라도 화물 특성이 전혀 다를 수 있음.
- 시스템이 부킹 번호를 의사결정에 쓰면, 다른 도착항/다른 양식의 샘플에서 의미 없는 정렬이 발생해 회귀.

**대신:** 부킹 anchor (같은 부킹은 같은 컨테이너) 룰만 유지. 번호 자체는 무시.

### ⑥ 엑셀 sub-table 구조 그대로 적재 계획

관찰: 엑셀의 No 컬럼이 1→13, 1→9, 1→4 로 재시작 → 실무자가 엑셀 작성 시점부터 그대로 컨테이너 분배로 사용.

**왜 룰로 안 쓰나:**
- 사용자가 엑셀 양식을 자유롭게 작성. sub-table 구분이 없는 양식도 많음 (단일 표).
- 엑셀 sub-table 신호를 의존하면 양식 작성 방식에 따라 시스템이 달라짐 — 일관성 깨짐.
- 시스템은 화물 데이터 자체로 최적 분배를 산출해야 함. 엑셀 표 구조는 단순 입력 형식.

**대신:** 화물 데이터(CBM·무게·사이즈·부킹·remarks)만 보고 룰 기반 분배.
