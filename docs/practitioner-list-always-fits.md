## 절대 명제

> **실무자가 짠 컨테이너 분배 리스트는 항상**
> - **컨테이너 규격(W·L·H·무게 한도)에 정확히 들어가고**
> - **모든 물리 규칙(OOB·충돌·받침)을 만족하며**
> - **여유 공간(slack)이 남는다.**

이는 4 샘플(1ST SG, 2ST SG, 1ST HM, 2ST HM) 모두에서 검증된 사실:

| 샘플 | 실무자 분배 강제 시 검증 결과 |
|---|---|
| 1ST SG TOTAL | ✅ 모든 물리·룰 통과 |
| 2ST SG TOTAL | ✅ 23 pass / 0 fail (force 강제 시) |
| 1ST HM TOTAL | ✅ 모든 물리·룰 통과 |
| 2ST HM TOTAL | ✅ **20 pass / 0 fail** (verify-2st-hm-practitioner.mjs) |

2ST HM 의 경우 적재율:
- 40FT-1: CBM 76%, 무게 64%
- 40FT-2: CBM 70%, 무게 71%
- 20FT-3: CBM 46%, 무게 20%

→ **항상 여유 공간 존재**.

## 알고리즘 설계 시 함의

### 1. 시스템 분배가 실무자와 다르다 ≠ 시스템이 더 좋다

시스템이 "더 효율적인" 분배를 만든 것처럼 보여도 실무자 분배 자체가 이미 물리·규격·룰을 모두 만족하는 유효 해(解). 차이는 **공간 효율 만이 아닌** 다른 알고리즘 제약(CBM 균형·무게 균형·큰 화물 분산·작은 부킹 마감 등) 때문.

### 2. 시스템 분배가 실무자보다 "꽉 찬" 결과를 내면 의심

실무자가 의도적으로 여유를 둔 곳에 시스템이 화물을 우겨 넣으면:
- **운송 안전 위험** (트림 불균형, 만재 흔들림)
- **실무자 의도 무시** (작은 부킹 마감 / 균형 분배 등)
- **회귀 위험** (실무자가 다음번에 같은 분배를 바꿀 수 있음 — 시스템 결과가 "쓸 수 없는 분배" 가 됨)

→ 시스템 분배의 적재율이 실무자보다 현저히 높다면 (예: 100% 만재 시도, 20FT 75% 이상 채움) **알고리즘 룰 의심**.

### 3. 임계값 설계 시 실무자 패턴 우선

CBM·무게 임계값을 결정할 때:
- 실무자가 **무엇을 20FT 에 보냈는지** 의 평균·중간값을 신뢰
- 실무자가 **무엇을 40FT 에 보냈는지** 의 평균·중간값을 신뢰
- 시스템이 실무자 분배를 재현하지 못한다면 임계값이 잘못됐거나, 룰이 잘못 모델링된 것

### 4. 회귀 발생 시 즉시 원복

알고리즘 룰을 추가했을 때 기존 샘플(1ST SG, 1ST HM, 2ST SG) 의 분배가 깨지면:
- 그 룰은 **실무자 의도와 충돌**
- 즉시 원복하고 새 룰 설계
- 단순 분류 룰("CT 만 20FT") 같은 거친 룰은 거의 항상 회귀 발생

## 실무자 분배가 항상 들어가는 이유 (추론)

1. **수년간의 경험** — 어떤 화물이 어디 들어가는지 직관 축적
2. **여유 공간 의도** — 운송 중 흔들림·검수 시 빈 공간 필요
3. **무게 균형** — 본선 트림 안정
4. **작업 흐름 최적화** — 한 컨에 모인 화물이 같은 작업 일정으로 처리 가능
5. **위험 회피** — 만재 직전 조합 본능적 회피
